# Совместные поездки Uber/Lyft: очистка данных, витрины и проверка гипотез

`shared_rides_pipeline.py` — единый скрипт полного аналитического пайплайна по данным NYC FHVHV tripdata: загрузка → очистка → витрины → проверка трёх гипотез о шеринге.

## Данные

- **Источник:** TLC Trip Record Data, FHVHV tripdata (`archive/fhvhv_tripdata_*.parquet`), период **2025-01 … 2026-04** (16 месяцев, ~324 млн строк после очистки).
- **Провайдеры:** Uber (`HV0003`) и Lyft (`HV0005`).
- **Справочник зон:** `taxi_zone_lookup.csv`.
- Ключевые поля: `shared_request_flag` (запрос шеринга) и `shared_match_flag` (факт нахождения пары).
  - у **Uber** нет комбинации `NY`: поиск пары начинается только после запроса шеринга;
  - у **Lyft** комбинация `NY` встречается: пользователь соглашается на шеринг, система автоматически ищет пару;
  - объёмы совместных поездок у сервисов несопоставимы напрямую.

Шеринг считается как любая комбинация флагов кроме `NN`, т.е. `YY + YN + NY`.

## Требования

Python 3.11+:

```bash
pip install duckdb pyarrow pandas scipy statsmodels matplotlib
```

Рядом со скриптом должны лежать папка `archive/` с parquet-файлами и `taxi_zone_lookup.csv`.

## Запуск

```bash
python3 shared_rides_pipeline.py                  # полный прогон (~4 мин на всех данных)
python3 shared_rides_pipeline.py --limit 500000   # быстрый смоук на случайном срезе
python3 shared_rides_pipeline.py --no-plots       # без графиков
python3 shared_rides_pipeline.py --export-csv out # витрины в out_*.csv
```

## Структура пайплайна

| Этап | Функции |

| Загрузка | `connect_duckdb()`, `load_trips()` |

## Гипотезы и результаты

Данные: полный прогон по всем 16 месяцам (323 552 925 поездок, из них shared — 8 288 687, 2.56%).

### H1. Чем длиннее поездка, тем выше вероятность шеринга
Группировка по длительности (0–10 … 60+ мин) + χ²-тест независимости + GLM Binomial.
- χ² = 1 414 778.81, df = 5, **p ≈ 0** → связь значима; все коэффициенты GLM значимы (p < 0.05).
- Эффект нелинейный: доля Shared растёт с ~1.7% (0–10 мин) до максимума ~5.9% (45–60 мин), у 60+ снижается.

### H2. Шеринг зависит от времени суток
Доли Shared по часам + χ²-тест; Peak (будни 7–9, 17–19; выходные 0–2, 10–15 ч) vs Non-peak + Z-тест долей + 95% ДИ разности.
- χ² = 938 226.31, df = 23, **p ≈ 0**; Z = 192.97, **p ≈ 0**.
- Разница: −0.353 п.п. (2.335% Peak против 2.689% Non-peak), 95% CI [−0.3568; −0.3498] — в Peak шеринг значимо реже.

### H3. Чем выше загруженность зоны, тем выше Match Rate Shared
Уровень зон Uber (≥100 запросов шеринга, 257 зон) + корреляция Спирмена.
- ρ = 0.6287, **p = 1.1e-29** → сильная монотонная положительная связь: в загруженных зонах пары находятся чаще.

Все три гипотезы подтверждены (α = 0.05).

## Витрины на выходе

- `mart_shared_daily` — 970 строк (день × провайдер): основа дашборда;
- `top20_zone_match` — 517 строк (провайдер × зона, match rate);
- `shared_heatmap` — 336 строк (провайдер × день недели × час, % запросов шеринга).

При `--export-csv PREFIX` витрины сохраняются в CSV.
