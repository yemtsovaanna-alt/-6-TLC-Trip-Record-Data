# Процесс разработки

## Ветки

- Прямой push в `main` запрещен (branch protection: PR + минимум 1 апрув +
  зеленый CI обязательны). Настройка — в Settings → Branches репозитория на
  GitHub (не хранится файлом в репо, GitHub API/UI — источник истины).
- Работа ведется в feature-ветках, названных по задаче, например
  `12-fix-zone-map-colors` (`12` — номер issue).

## Ревью

- Обязательные ревьюверы — [`.github/CODEOWNERS`](.github/CODEOWNERS).
- PR не мержится без апрува хотя бы одного code owner.

## CI

- [`.github/workflows/ci.yaml`](.github/workflows/ci.yaml): build, test, deploy
  (сейчас — заглушки) + проверка, что в названии PR указан номер задачи.

## Задачи и PR

- Любая работа начинается с Issue ("Задачи") в этом репозитории.
- Название PR обязано содержать номер задачи, например:
  `#12 Fix zone map colors`.
- PR стоит связывать с задачей через `Closes #12` в описании — тогда issue
  закроется автоматически при мерже.
